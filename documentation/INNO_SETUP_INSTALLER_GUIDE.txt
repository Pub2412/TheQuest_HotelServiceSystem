THE QUEST HOTEL SERVICE SYSTEM
INNO SETUP INSTALLER GUIDE
========================================

This guide explains how to create one suite installer for The Quest Hotel
Service System. During setup, the user must choose exactly one product:
Company Desktop App, Customer Website, or Mobile Apps. Supporting files are
installed automatically with the selected product and are not separate user
choices.


1. RELEASE CONTENTS
-------------------

The single installer must contain these three selectable products:

  TheQuestSuiteSetup.exe
    Company Desktop App
      Smart Lock Simulator (installed with the desktop app)
    Customer Website
    Mobile Apps
      Company Mobile backend server
      Customer Mobile backend server
      Company Mobile APK
      Customer Mobile APK
      ADB launcher
      Android SDK and Pixel 6 Emulator

The three products are mutually exclusive choices. The Smart Lock Simulator
is a desktop-app dependency, while the mobile backends, APKs, ADB launcher,
Android SDK, and emulator are mobile-app dependencies. SQLite command-line
tools are not an installer choice and are not included in the product
installation.


2. PREPARE THE STAGING FOLDERS
------------------------------

Create one staging folder outside the source folders:

  installer-files\
    desktop\
      TheQuestDesktop.exe
    smart-lock\
      SmartLockSimulator.exe
    website\
      CustomerWebsite.exe
    mobile-servers\
      CompanyMobileServer.exe
      CustomerMobileServer.exe
    apk\
      TheQuest_Company.apk
      TheQuest_Customer.apk
    android\
      sdk\
      adb-launcher.bat
    assets\
      imgs\
        logo\
          logo.png
          logotitle.png
          logo.ico
    database\
      hotel_service.db
    sqlite\
      sqlite3.exe
      sqldiff.exe
      sqlite3_analyzer.exe

All components use the same writable SQLite database. SQLite is the
database engine used here; "MySQL Lite" is not a separate database product.
The installer copies the single tested hotel_service.db file to
{commonappdata}\The Quest Hotel\database. Do not bundle another database copy
inside an executable or APK.
Do not copy passwords, credentials, private keys, or production database
copies into the installer unless they are intentionally required.


3. BUILD THE WINDOWS APPLICATIONS
---------------------------------

Build the Desktop App and Smart Lock Simulator as standalone executables so
the target computer does not need Python or pip.

Install PyInstaller in the virtual environment:

  python -m pip install pyinstaller

Build the Company Desktop App:

  cd TheQuest_Company_DesktopApp
  pyinstaller --noconfirm --clean --windowed ^
    --name TheQuestDesktop ^
    --icon ..\assets\imgs\logo\logo.ico ^
    --add-data "..\assets;assets" ^
    main.py

Copy the resulting executable from dist\TheQuestDesktop\ to
installer-files\desktop\TheQuestDesktop.exe.

Build the Smart Lock Simulator:

  pyinstaller --noconfirm --clean --windowed ^
    --name SmartLockSimulator ^
    --icon ..\assets\imgs\logo\logo.ico ^
    --add-data "..\assets;assets" ^
    ..\gui.py

Copy the resulting executable from dist\SmartLockSimulator\ to
installer-files\smart-lock\SmartLockSimulator.exe.

For the Customer Website, create a launcher that starts the local server and
opens the browser. Package the launcher with its templates, static files,
backend modules, assets, and the database package (Python modules only).
Do not package database\hotel_service.db in the executable. Copy the tested
launcher executable to installer-files\website\CustomerWebsite.exe.

Use a different local port if the website can run at the same time as another
local server. Test every executable on a computer that does not have the
development virtual environment installed.


4. PREPARE THE MOBILE AND ANDROID COMPONENTS
---------------------------------------------

The Android SDK and emulator are installed automatically when Mobile Apps is
selected because they are required to run the bundled mobile applications.
They require substantial disk space and may require hardware virtualization.

Prepare and test:

  - Android SDK command-line tools
  - Android Platform Tools
  - Android Emulator
  - Android platform 35
  - A compatible Android 35 system image
  - Pixel 6 AVD
  - Company Mobile APK
  - Customer Mobile APK
  - Company Mobile backend server
  - Customer Mobile backend server
  - ADB launcher

Copy the complete tested SDK folder into installer-files\android\sdk\.
Copy the two tested APK files into installer-files\apk\.
Build the Company Mobile and Customer Mobile backend servers as tested
executables and copy them into
installer-files\mobile-servers\. The Android APKs do not open a
Windows file path directly: the backend servers use the shared database at
{commonappdata}\The Quest Hotel\database\hotel_service.db, and the ADB
launcher must start or connect to those servers before an APK is launched.
Create adb-launcher.bat so it uses the SDK's platform-tools\adb.exe, then
copy it into installer-files\android\.

Typical SDK setup commands are:

  sdkmanager "platform-tools" "emulator" "platforms;android-35" ^
    "system-images;android-35;google_apis;x86_64"

  avdmanager create avd --name "TheQuest_Pixel_6" ^
    --package "system-images;android-35;google_apis;x86_64" ^
    --device "pixel_6"

The Pixel 6 emulator may fail if CPU virtualization is disabled in BIOS or
Windows virtualization support is unavailable. Test the emulator before
compiling the final installer. The Company Desktop App and Customer Website
must still be able to install and run without the Android SDK.


5. CREATE THEQUESTSUITESETUP.ISS
--------------------------------

Open Inno Setup Compiler, choose File > New, and save the script as
TheQuestSuiteSetup.iss. Use this setup:

  [Setup]
  AppName=The Quest Hotel Service System
  AppVersion=1.0.0
  DefaultDirName={autopf}\The Quest Hotel
  DefaultGroupName=The Quest Hotel
  OutputBaseFilename=TheQuestSuiteSetup
  OutputDir=installer-output
  ArchitecturesInstallIn64BitMode=x64
  PrivilegesRequired=admin
  UninstallDisplayIcon={app}\assets\imgs\logo\logo.ico

  [Types]
  Name: "desktop"; Description: "Company Desktop App"
  Name: "website"; Description: "Customer Website"
  Name: "mobile"; Description: "Mobile Apps"

  [Components]
  Name: "desktop"; Description: "Company Desktop App"; Types: desktop
  Name: "website"; Description: "Customer Website"; Types: website
  Name: "mobile"; Description: "Mobile Apps"; Types: mobile

Do not add a Custom installation type or separate smart-lock, Android, or
SQLite components. The selected type is the only product the user can choose.
The desktop product includes the Smart Lock Simulator, and the mobile product
includes both mobile backend servers, both APKs, the ADB launcher, the SDK,
and the emulator.


6. ADD THEQUESTSUITESETUP FILES AND SHORTCUTS
---------------------------------------------

Add these sections to TheQuestSuiteSetup.iss:

  [Files]
  Source: "installer-files\desktop\TheQuestDesktop.exe"; \
    DestDir: "{app}\Desktop"; Components: desktop
  Source: "installer-files\smart-lock\SmartLockSimulator.exe"; \
    DestDir: "{app}\SmartLock"; Components: desktop
  Source: "installer-files\website\CustomerWebsite.exe"; \
    DestDir: "{app}\CustomerWebsite"; Components: website
  Source: "installer-files\mobile-servers\CompanyMobileServer.exe"; \
    DestDir: "{app}\mobile-servers"; Components: mobile
  Source: "installer-files\mobile-servers\CustomerMobileServer.exe"; \
    DestDir: "{app}\mobile-servers"; Components: mobile
  Source: "installer-files\apk\TheQuest_Company.apk"; \
    DestDir: "{app}\apk"; Components: mobile
  Source: "installer-files\apk\TheQuest_Customer.apk"; \
    DestDir: "{app}\apk"; Components: mobile
  Source: "installer-files\android\adb-launcher.bat"; \
    DestDir: "{app}\android"; Components: mobile
  Source: "installer-files\android\sdk\*"; \
    DestDir: "{app}\android\sdk"; \
    Flags: recursesubdirs createallsubdirs; Components: mobile
  Source: "installer-files\assets\*"; DestDir: "{app}\assets"; \
    Flags: recursesubdirs createallsubdirs
  Source: "installer-files\database\hotel_service.db"; \
    DestDir: "{commonappdata}\The Quest Hotel\database"; \
    Flags: onlyifdoesntexist uninsneveruninstall
  [Icons]
  Name: "{group}\The Quest Desktop App"; \
    Filename: "{app}\Desktop\TheQuestDesktop.exe"; \
    WorkingDir: "{app}\Desktop"; \
    IconFilename: "{app}\assets\imgs\logo\logo.ico"; Components: desktop
  Name: "{group}\Smart Lock Simulator"; \
    Filename: "{app}\SmartLock\SmartLockSimulator.exe"; \
    WorkingDir: "{app}\SmartLock"; \
    IconFilename: "{app}\assets\imgs\logo\logo.ico"; Components: desktop
  Name: "{group}\Customer Website"; \
    Filename: "{app}\CustomerWebsite\CustomerWebsite.exe"; \
    WorkingDir: "{app}\CustomerWebsite"; \
    IconFilename: "{app}\assets\imgs\logo\logo.ico"; Components: website
  Name: "{group}\ADB launcher"; \
    Filename: "{app}\android\adb-launcher.bat"; \
    WorkingDir: "{app}\android"; Components: mobile

Use {commondesktop} instead of {group} when a desktop shortcut is required.
The applications resolve the shared database through the
QUEST_HOTEL_DATABASE environment variable when set, then
{commonappdata}\The Quest Hotel\database\hotel_service.db, and finally the
source-tree database for development. Use {commonappdata} for writable
databases and logs. Program Files should be treated as read-only.


The suite installer must install only the selected product and its required
supporting files. Verify that the launcher points to the installed SDK and
backend paths rather than development-machine paths. The mobile backends must
use the same common database copy before either APK is launched.


7. PYTHON AND SQLITE REQUIREMENTS
---------------------------------

If the Desktop App, Smart Lock Simulator, and Customer Website are packaged
with PyInstaller, Python does not need to be installed on the target
computer. Python and the application requirements are bundled into the EXE
files.

If source code is distributed instead, Python and each requirements.txt file
must be installed separately. This is less reliable because it depends on
network access, Python versions, and package compatibility. PyInstaller is
recommended.

Python's sqlite3 module is already available to Python applications. The
Company Mobile APK and Customer Mobile APK use the same SQLite database
through their backend services. The suite installer includes one database
copy only and does not install command-line SQLite tools.


8. OPTIONAL PREREQUISITE CHECKS
-------------------------------

Do not silently replace working installations. A prerequisite workflow should:

  1. Detect the installed tool or runtime.
  2. Show what is missing.
  3. Ask the user whether to install it.
  4. Run the prerequisite installer or show an actionable error.
  5. Continue only after a successful installation.

Use the [Run] section only for prerequisites that are actually required. For
example, a source-code distribution may use:

  [Run]
  Filename: "{tmp}\python-installer.exe"; \
    Parameters: "/quiet InstallAllUsers=1 PrependPath=1"; \
    StatusMsg: "Installing Python..."; Flags: waituntilterminated

Do not add a Python prerequisite to the recommended PyInstaller-based release.


9. COMPILE AND TEST
--------------------

Compile the suite installer:

  1. Open TheQuestSuiteSetup.iss.
  2. Select Build > Compile.
  3. Verify TheQuestSuiteSetup.exe in installer-output\.
  4. Install it on a clean Windows test computer.
  5. Test each of the three product choices independently.
  6. Confirm shortcuts use the Quest icon.
  7. Confirm the shared database is writable.
  8. Test uninstall and verify that user data is not accidentally deleted.
  9. For the Mobile Apps choice, confirm both mobile backends use
     {commonappdata}\The Quest Hotel\database\hotel_service.db.
  10. For the Mobile Apps choice, install and launch both APKs.
  11. For the Mobile Apps choice, start the Pixel 6 emulator.
  12. For the Mobile Apps choice, test database-backed login, rooms, services,
      and reservations in both mobile applications.
  13. Test with virtualization enabled and record the expected error when it
      is unavailable.

Test one installation for each product choice. Selecting Company Desktop App
must not install the website or mobile files; selecting Customer Website must
not install the desktop or mobile files; and selecting Mobile Apps must
install both mobile applications and all of their required Android files.
Each selected product must continue to use the one writable shared database.
